Three Approaches to Tree-First Editing

Pick the architecture that feels right. We'll flesh out the details next.

A

Incremental Enhancement Recommended

Extend PersonPanel.vue in place. Add editable header fields, remove readonly from EventList, add new Sources and Groups sections, add "+" buttons to nodes and panel header. Collapsible sections handle space.

Pros

  • Minimal disruption to existing code
  • Collapsible sections already handle breadth
  • No mode-switching cognitive overhead
  • Genealogy work is always in "edit mode" — no toggle needed

Cons

  • PersonPanel.vue grows larger
  • All sections visible = longer scroll
B

View / Edit Mode Toggle

Panel has two modes: compact "view" (name, dates, bullet summaries) and "edit" mode (full editable sections). A pencil icon switches modes. "+" button lives in both modes.

Pros

  • Compact view is good for browsing the tree
  • Edit mode is focused

Cons

  • Extra click to enter edit mode
  • Genealogy work is almost always editing — toggle becomes friction
  • More state to manage
C

Tab-Based Panel

Panel has tabs: Overview · Events · Sources · Groups. Each tab is a focused editing surface. "+" button lives in the Overview tab.

Pros

  • Each tab can be deep without scrolling
  • Clean separation per concern

Cons

  • Tabs inside a panel inside a view = deep navigation nesting
  • Can't see events and sources at the same time
  • More complex to implement
