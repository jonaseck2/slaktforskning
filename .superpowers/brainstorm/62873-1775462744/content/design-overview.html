Design overview — infinite expansion

Three layers of changes. Does this structure look right?

1. Data layer chartData.ts

  • At fetch time (deepest generation): after loading each leaf person, also fetch their relationships — 1 extra IPC call per leaf — to check whether parents/children exist in the DB. Stored as hasMoreAncestors: Set<number> on PedigreeTree and hasMoreChildren: boolean on DescendantNode.
  • New loadAncestorGeneration(tree, ahnNum): fetches the 2 parents of a given ahnentafel node, adds them to tree.nodes, checks their parents, updates hasMoreAncestors. Returns a new tree object (Vue reactivity).
  • New loadChildrenForNode(node): fetches children for a DescendantNode, attaches them, sets hasMoreChildren on each new child.

2. Layout layer chartLayout.ts

  • Add isLoadMore: boolean to CollapseButton — same visual (directional arrow), but the component routes the click differently.
  • Pedigree: change collapse button direction 'up' → 'right' (▲ → ▶). The button was already positioned to the right of the box — just the arrow symbol and key name change. Generates load-more buttons (▶, isLoadMore: true) for any leaf where hasMoreAncestors is set.
  • Hourglass ancestors: stays 'up' (▲ correct — ancestors go upward). Generates load-more buttons for leaves in hasMoreAncestors.
  • Hourglass descendants: generates load-more (▼, isLoadMore: true) for descendant leaves where hasMoreChildren: true.

3. Component layer PedigreeChart.vue · HourglassChart.vue

  • toggle(personId, dir) checks btn.isLoadMore: if true, calls the appropriate load function and replaces tree.value with the updated tree. If false, existing toggle-collapsed logic unchanged.
  • No separate loading spinner per branch — the tree just grows on click. Full-tree loading spinner only on initial load.
Not in scope: the pedigree arrow direction fix (:up → :right) is a 3-line change included in this same feature.
