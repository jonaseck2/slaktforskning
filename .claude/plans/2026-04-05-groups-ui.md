# Groups UI — Design Spec

## Goal

Add a complete Groups UI to the app: a list view to manage groups, a detail view showing members, and a section in PersonDetailView to add/remove a person from groups. Also update the sidebar navigation with icons and Swedish labels.

## Background

The full backend is already in place — `window.api.groups.*` (list, get, create, update, delete, addMember, removeMember, forPerson) covers all operations. No API, IPC, or MCP changes are needed. This is a pure UI build.

## Architecture

**New files:**
- `src/renderer/views/GroupsView.vue` — list view at `/groups`
- `src/renderer/views/GroupDetailView.vue` — detail view at `/groups/:id`
- `src/renderer/components/GroupPicker.vue` — autocomplete input for selecting or creating a group

**Modified files:**
- `src/renderer/router.ts` — two new routes
- `src/renderer/App.vue` — sidebar nav with icons + Groups entry
- `src/renderer/views/PersonDetailView.vue` — new Groups section
- `src/renderer/i18n/sv.ts` + `en.ts` — new translation keys

## Feature: GroupsView (`/groups`)

- Header: "Grupper" title + "+ Lägg till grupp" button (top right)
- Table columns: Namn | Medlemmar (count) | Anteckningar | Åtgärder
- Each row is clickable → navigates to `/groups/:id`
- Delete button per row with confirmation dialog (`confirm()`)
- Member count loaded via `window.api.groups.getMembers(id)` per row during `load()`
- Empty state message when no groups exist
- "+ Lägg till grupp" opens a modal with:
  - Name field (required, text input)
  - Notes field (optional, textarea)
  - Cancel / Spara buttons
- Reactively reloads on `onDataChanged`

---

## Feature: GroupDetailView (`/groups/:id`)

- Back link: `← Grupper` → `/groups`
- Group name: inline-editable `<input>`, auto-saves on blur
- Group notes: inline-editable `<textarea>`, auto-saves on blur
- Members section header: "Medlemmar (N)" count + "+ Lägg till" button
  - Clicking "+ Lägg till" shows `PersonPicker` (autocomplete) inline below the header
  - Selecting a person from picker calls `window.api.groups.addMember(groupId, personId)` and reloads
  - "Avbryt" link collapses the picker
- Members table columns: Namn | Kön | Åtgärder
  - Name is a `<router-link>` to `/persons/:id`
  - Sex shown as M/K/–
  - "Ta bort" button removes member with `window.api.groups.removeMember(groupId, personId)` + reload

**Note:** GroupDetailView adds members from persons. The "search" in the add-member flow uses `window.api.persons.search()` — same as PersonPicker. This is distinct from GroupPicker (used in PersonDetailView).

---

## Feature: GroupPicker component

A new `GroupPicker.vue` component for use in PersonDetailView — mirrors `PlacePicker.vue`:

- Props: `personId: string` (to know which groups to exclude)
- Emits: `added` (after successfully adding person to group)
- 150ms debounced search via `window.api.groups.list()` filtered client-side (groups are few, no server search needed)
- Dropdown shows matching groups the person is NOT already in
- Bottom option: "＋ Skapa ny grupp '[query]'" — creates the group then adds member
- "Avbryt" link collapses the picker
- Pressing Escape collapses the picker

## Feature: PersonDetailView Groups section

New section added between Relationer and Anteckningar:

- Section heading: "Grupper (N)" where N is count of groups person belongs to
- Groups shown as **chips** (pill badges):
  - Blue background (`#eef2ff`), blue border, blue text
  - Group name is a `<router-link>` to `/groups/:id`
  - × button on each chip calls `window.api.groups.removeMember(groupId, personId)` + reload
- "+ Lägg till" button: shows `GroupPicker` inline below chips
- Empty state: "Inte med i någon grupp ännu." when no groups

## Data flow summary

- `GroupsView.load()` → `api.groups.list()` + per-row `api.groups.getMembers(id)` for count
- `GroupDetailView.load()` → `api.groups.get(id)` + `api.groups.getMembers(id)` → names via `api.persons.getNames()`
- `PersonDetailView` groups load → `api.groups.forPerson(personId)` on mount + after mutations
- `GroupPicker` search → `api.groups.list()` filtered client-side (exclude already-joined groups)
- All mutations fire `onDataChanged` → reactive badge/list updates
