# Plan: Media Attachments

## Context
Genney has MEDIA (4 rows) and OWNER_MEDIA tables. Media items have FILEREF (path), TITLE, FORMAT, ISPRINTABLE, NOTE. Owners can be persons, events, families (relationships), or sources. The goal is rich media integration for printable output in the future.

The schema, API, IPC, preload, and Genney import (metadata only) are already wired (v0.7.0). This plan covers file handling and the full UI feature.

## Data Model (already implemented)

```sql
media (id, file_ref TEXT, title TEXT, format TEXT, notes TEXT, is_printable INTEGER, created_at)
media_links (id, media_id, entity_type TEXT, entity_id TEXT, link_type INTEGER, created_at)
-- entity_type: 'person' | 'event' | 'relationship' | 'place' | 'source'
```

## Phase 1 — File handling (prerequisite for meaningful UI)

### File storage strategy
Two approaches to consider:

**A. Copy-into-database-folder (recommended)**
When the user attaches a file, copy it to a `media/` subfolder next to the `.db` file. Store the relative path in `file_ref`. This keeps the database self-contained for backup and migration.
- Pro: Works when moving the database, survives file renames at the source.
- Con: Duplicates disk space.

**B. Absolute path reference**
Store the original absolute path. Do not copy.
- Pro: No disk duplication.
- Con: Breaks if user moves or renames the source file; does not survive database migration.

**Decision needed**: Strategy A is recommended for genealogy (data preservation), but the user should confirm.

### File import from Genney .backup
Genney MEDIA.FILEREF stores a relative path within the backup archive. During import, if the archive contains the file, extract it to the `media/` folder beside the database. If not present (external reference), store the path and mark as `missing`.
- Add `is_missing INTEGER DEFAULT 0` column to `media` table.
- During Genney import: check if the archive contains the referenced path; if yes, extract and copy; if no, set `is_missing = 1`.

## Phase 2 — IPC additions needed
- `media:attach` — dialog to pick a file + copy to media folder, return media record
- `media:getFile` — return the resolved absolute path for display (electron `shell.openPath`)
- `media:openFile` — open in default OS viewer via `shell.openPath`
- `media:exportFile` — copy out to user-chosen destination

## Phase 3 — UI

### MediaView at `/media`
- Grid/list of all media (thumbnail if image, icon if document)
- Filter by entity type (persons, events, places, sources)
- Click → detail panel: title, format, linked entities, file preview
- "Attach" button → file picker → attach to entity

### Inline in detail views
- PersonDetailView: "Media" section showing thumbnails/file names attached to this person
- EventForm/EventList: each event row shows media count badge; expand to see attachments
- SourceDetailView: "Attachments" section for source documents

### Image handling
- For image formats (jpg, png, gif, webp, tiff): show thumbnail using Electron's `nativeImage` or an `<img>` tag with a `file://` URL
- For documents (pdf, doc, etc.): show a file icon with the format label

## Phase 4 — Geographic tagging in images (future)
EXIF GPS coordinates can be read from photos and used to:
- Suggest a place link when attaching an image
- Display the photo on a map in the places view
- This is a deferred enhancement, not part of Phase 1–3.
